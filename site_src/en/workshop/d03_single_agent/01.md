# D3-1: Bicep Resource Deployment / D3-1: Bicep 资源部署

> 时长：约 40 min ｜ 凭证：有 Azure 订阅 + Foundry project 学员自跑；无凭证学员观看讲师演示并拿模板 ｜ 类型：讲师演示 + 学员实操

## Background / 背景
- D3 第一步：把 Foundry project 的 agent + connection 资源用 Bicep 创建出来
- 上游 Ex01 提供 Bicep 模板结构作为参考；本课让 AI 帮你写 module 化版本，你审 diff
- 后两步要在这资源上跑代码 + 看 trace，所以这一步是"先有资源才有后续"

## What You Need to Do / 你需要做什么
1. 把下面 prompt 给 AI（Claude Code / Codex / Copilot 任选），让它生成 Bicep：

   ```text
   帮我写一个 Foundry 单 agent 部署的 Bicep，要求：
   - module 化（agent / connection 分文件，main.bicep 装配）
   - 模型部署名走 parameter，不写死
   - secret 走 Key Vault 引用或 env，不 hardcode
   - 输出资源不要多余（不要带额外 storage / log workspace 除非必需）

   我的 project 名：[…]
   Region：[…]
   模型部署名：[…]
   ```

2. **审 diff**：AI 生成后逐文件读一遍，重点看：
   - 有没有偷偷多创资源
   - parameter 是不是真的拆出来了
   - 有没有任何字符串看起来像 secret
3. 有订阅学员：

   ```bash
   az login
   az deployment group create \
     --resource-group <rg> \
     --template-file main.bicep \
     --parameters modelDeploymentName=<name>
   ```

4. 无订阅学员：跟讲师演示走，拿到模板拷回去；记下"换 region 要改 main.bicep 哪几行"

## Tips / 提示
- AI 经常把"以防万一"的资源（storage account / log workspace）塞进来，审 diff 时砍掉
- Bicep 用 module 是为了 D5 部署到 Hosted Agents 主路径时 agent / connection 资源好独立维护；如果走 ACA 对照路径，module 化也能减少耦合（D5 ACA 段会引用）
- 如果 az deployment 报 "Quota exceeded"，回 D1 prep 阶段核对 TPM 配额

## Self-Check / 自检
- [ ] Bicep 已 module 化（不是单文件 200 行）
- [ ] 模型部署名走 parameter
- [ ] 没有 hardcode 的 secret（grep "key\|secret\|password" 干净）
- [ ] 有订阅：az deployment 成功无 error；无订阅：能讲清 module 拆分 + 换 region 要改哪几行

## Submission (Counts Toward Capstone) / 提交（计入综合作业）
- 产物：审过 diff 的 Bicep 模板（main.bicep + modules/）+ 部署日志截图（无订阅则模板 + 一段"我会怎么部署"说明）
- 放：`submissions/d3_1_bicep/`

## Negative Examples / 反例
- 让 AI 生成 Bicep 后直接 `az deploy` 不审 diff —— AI 经常多创资源
- 模型部署名写死 —— 不同环境必走 parameter；rebrand 期模型名经常改
- 把 connection string 塞 .env 提交 git —— Key Vault + Managed Identity 是默认路径
