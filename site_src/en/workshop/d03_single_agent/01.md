# D3-01: Bicep Resource Deployment

> Module: D3 Single-Agent Platform Path | Credentials: Azure subscription and Foundry project for real deployment; mock or instructor endpoint for fallback

## Purpose
Generate, review, and optionally run modular Bicep for agent resources. This step turns the module decision into a concrete learner artifact that can be reviewed during class.

## Instructions
- Bring forward the D2 traffic and token assumptions.
- Choose the deployment target and capacity mode before writing runtime safeguards.
- Record best-case and worst-case monthly cost with the dominant cost driver.

## Acceptance Criteria
- The requested artifact exists and can be reviewed by the instructor or assistant.
- The artifact uses concrete values from your project rather than generic placeholders.
- Any uncertainty is written explicitly instead of hidden.
- The output remains consistent with earlier decision cards unless you document why the decision changed.

## Submission
- Save the artifact in the matching `submissions/` folder for this step.
- Include short notes, screenshots, logs, or trace links only when they prove the acceptance criteria.

## Common Mistakes
- Deploying AI-generated Bicep without reading the diff.
- Hardcoding model deployment names or secrets.
- Writing retry logic in this step instead of leaving retry strategy for D5.
