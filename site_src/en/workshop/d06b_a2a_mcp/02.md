# D6b-02: Add an MCP Tool to the A2A Chain

> Module: D6b A2A + MCP Boundary | Credentials: Local demos and prepared traces; no remote MCP server required

## Purpose
Attach a real local file, HTTP, or calculation tool. This step turns the module decision into a concrete learner artifact that can be reviewed during class.

## Instructions
- Run one local A2A or MCP path, or inspect the instructor prepared trace.
- Verify that agent-to-agent communication is not an in-process function call.
- Estimate added token, latency, process, and network costs.
- If overlaying A2A and MCP, identify the three-hop trace.

## Acceptance Criteria
- The requested artifact exists and can be reviewed by the instructor or assistant.
- The artifact uses concrete values from your project rather than generic placeholders.
- Any uncertainty is written explicitly instead of hidden.
- The output remains consistent with earlier decision cards unless you document why the decision changed.

## Submission
- Save the artifact in the matching `submissions/` folder for this step.
- Include short notes, screenshots, logs, or trace links only when they prove the acceptance criteria.

## Common Mistakes
- Wrapping a local function as MCP only to add operational burden.
- Using echo-only MCP tools.
- Ignoring doubled token cost and doubled failure surface.
