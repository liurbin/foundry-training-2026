# D6a-01: Rewrite the D3 Agent with the SDK Path

> Module: D6a Agent Framework SDK Boundary | Credentials: Mock provider is enough

## Purpose
Create a minimal SDK version that runs locally. This step turns the module decision into a concrete learner artifact that can be reviewed during class.

## Instructions
- Implement the smallest SDK-path equivalent of the D3 agent.
- Compare it with the Agent Service path across code, dependencies, startup, observability, state, and operations.
- Record whether switching is justified by business constraints, not code aesthetics.

## Acceptance Criteria
- The requested artifact exists and can be reviewed by the instructor or assistant.
- The artifact uses concrete values from your project rather than generic placeholders.
- Any uncertainty is written explicitly instead of hidden.
- The output remains consistent with earlier decision cards unless you document why the decision changed.

## Submission
- Save the artifact in the matching `submissions/` folder for this step.
- Include short notes, screenshots, logs, or trace links only when they prove the acceptance criteria.

## Common Mistakes
- Switching to SDK because the code looks cleaner.
- Running SDK self-hosted without observability.
- Keeping both paths without a business reason.
