# D2-01: Architecture Overview and Capability Boundaries

> Module: D2 Agent Service vs SDK Selection | Credentials: None

## Purpose
Map runtime ownership, state ownership, portal visibility, and code control. This step turns the module decision into a concrete learner artifact that can be reviewed during class.

## Instructions
- Read the module context and the linked instructor notes.
- Create the requested artifact for this step.
- Verify it against the checklist before review.

## Acceptance Criteria
- The requested artifact exists and can be reviewed by the instructor or assistant.
- The artifact uses concrete values from your project rather than generic placeholders.
- Any uncertainty is written explicitly instead of hidden.
- The output remains consistent with earlier decision cards unless you document why the decision changed.

## Submission
- Save the artifact in the matching `submissions/` folder for this step.
- Include short notes, screenshots, logs, or trace links only when they prove the acceptance criteria.

## Common Mistakes
- Defaulting to SDK just because it is more flexible.
- Assuming managed service is always more expensive without counting self-hosting and on-call.
- Treating capacity decisions as afterthoughts instead of architecture inputs.
