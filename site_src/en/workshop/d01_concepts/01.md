# D1-1: Foundry Capability Map Overview / D1-1: Foundry 能力地图速览

> 时长：约 10 min ｜ 凭证：无 ｜ 类型：讲 + 自查

## Background / 背景
- 这是 D1 第一步：你要先知道 Foundry 整体覆盖哪些能力域，再判断你的项目落在哪一格
- 后续 D2-D5 每一格都会被单独拆开做决策，本步是地图，后面是航线
- 与 D10（能力边界表）互为镜像：本表讲"覆盖范围"，D10 讲"不能做什么"

## What You Need to Do / 你需要做什么
1. 打开训练计划五·五节 Foundry 能力地图（参考链接见底部）
2. 对照下面 14 个能力域，逐项判断"我项目当前/计划"是否用到：
   - Agent Service / Workflows / Projects / Connections / Identity / Models / Evaluations + Red Team / Tracing + Monitoring / Deployment / Quotas (PAYG) / Capacity (dedicated) / SDK / A2A / MCP
3. 在自己的笔记里画一张能力地图副本，每一格写一行："用 / 不用 / 不确定"
4. 圈出 1-2 格你**最不确定**的，记下来留到第 3 步评审时问

## Tips / 提示
- 不要纠结"应该用什么"，本步只标"现在/计划用什么"
- 不确定的格子比写错的格子有价值，第 3 步评审会优先讨论这些
- Agent Service vs SDK 这两格如果都勾"用"，正常；D2 会拆它们
- **Quotas (PAYG) 默认会勾"用"**（默认配额模式）；**Capacity (dedicated)** 是 PTU / reservation 这一类，只有"高吞吐 + SLA 承诺"或"长期稳定用量要锁价"才勾"用"——多数项目这里勾"不用"或"不确定"

## Self-Check / 自检
- [ ] 14 个能力域全部标注，没有空格
- [ ] 至少有 1 格标"不确定"（如果你 14 格全勾"用"，说明没认真看 D10 的镜像表）
- [ ] 能口头说出"我项目目前主要落在哪 2-3 格"

## Submission (Counts Toward Capstone) / 提交（计入综合作业）
- 产物：一张填好的 Foundry 能力地图（markdown 表或截图均可）
- 放：`submissions/d1_1_capability_map/map.md`

## Negative Examples / 反例
- "公司是 Azure 客户所以一定用 Foundry" —— 客户合同 ≠ 技术选型，地图上对应不到任何一格的"用"
- "Foundry 比 LangGraph 高级所以选 Foundry" —— 比较错位：托管平台 vs 编排库不在一个轴上
