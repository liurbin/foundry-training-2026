# D1-2: Complete the Foundry Fit Decision Card / D1-2: 填写"是否用 Foundry"决策卡

> 时长：约 20 min ｜ 凭证：无 ｜ 类型：练（无 AI-pair 实操，模板填空）

## Background / 背景
- 第 1 步你已经标出"项目落在哪几格"，本步要给一个明确结论：用 / 不用 / 部分用
- 这张卡是 D1 的主产出，也是综合作业架构选型决策卡的第一行
- 后面 D2/D4 都会引用这张卡的结论

## What You Need to Do / 你需要做什么
1. 在自己的笔记里新建 `decision_card.md`，拷入下面模板
2. 项目一句话描述：业务目标 + 当前阶段，1 行写完
3. 逐项勾选 8 条决策维度（4 条倾向 Foundry + 4 条不用），允许混合
4. 结论一栏写"用 / 不用 / 部分用"三选一，**不接受"再想想"**
5. 如果是"部分用"，对照第 1 步的地图指出至少 2 格
6. "我不确定的地方"一栏必须非空

模板：

```markdown
# My Project: Foundry Fit Decision Card / 我的项目：是否用 Foundry 决策卡

## 项目一句话描述
（业务目标 + 当前阶段）

## 决策维度勾选
- [ ] 需要托管 agent 运行时 + 状态管理 → 倾向 Foundry
- [ ] 需要 Azure 生态原生集成（AAD / Key Vault / App Insights）→ 倾向 Foundry
- [ ] 有合规/数据驻留要求 → 倾向 Foundry
- [ ] 需要 portal 上让非工程师配 agent / 看 trace → 倾向 Foundry
- [ ] 只需要单次 LLM call，无 agent 概念 → 不用 Foundry
- [ ] 核心模型在 Azure 目录外且不打算切 → 不用 Foundry
- [ ] 研究 demo / hackathon，下周扔 → 不用 Foundry
- [ ] 已有成熟 LangGraph / CrewAI 生产栈 → 不用 Foundry

## Conclusion / 结论
[用 / 不用 / 部分用]

## 部分用的话，哪一部分？
（对照第 1 步的能力地图）

## 我不确定的地方
（评审段必看）
```

## Tips / 提示
- 若只勾到单边（全 Foundry 或全不用），必须写一句"为什么对侧维度全不适用"
- "不确定的地方"不是失败标志，是诚实标志；空着反而扣分
- 不要把"以后再迁"写进结论 —— 迁移成本在写第一行代码时就决定（D10 会回这条）

## Self-Check / 自检
- [ ] 至少勾 1 个"倾向 Foundry" + 1 个"倾向不用"维度，或单边但有解释
- [ ] 结论明确，不是"再想想"
- [ ] "部分用"则在地图上指出 ≥2 格
- [ ] "我不确定的地方"非空

## Submission (Counts Toward Capstone) / 提交（计入综合作业）
- 产物：`decision_card.md`
- 放：`submissions/d1_2_decision_card/decision_card.md`
