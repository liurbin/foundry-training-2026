# D11-4: Copy the Directory Structure for Your Team / D11-4: 给自己团队抄一套目录结构

> 时长：约 10 min ｜ 凭证：你团队现有文档系统（git 仓库 / Confluence / Notion 都行）｜ 类型：练 + 评审

## Background / 背景
D11 收口产物——把 D11-1 的 5 目录结构、D11-2 选定的示例 spec、D11-3 的 prompt 模板，整体抄回你团队。

**验收口径硬性放宽**：截图或抄到团队文档即可，**不强制 git push**。本课 35 min 全程没有 git 实操窗口，不要因为推不上去就交白卷。

## What You Need to Do / 你需要做什么
1. 选一个你团队现有的承载位置（Git 仓库 / Confluence / Notion / 内网 Wiki 都行）
2. 把 5 目录结构搬过去（可以截图、可以新建空目录、可以只放 README）
3. 把 D11-2 选定的示例 spec 放进 `decision-cards/` 或 `implementation/` 对应位置
4. 在 README 写 3 件事：
   - 谁可以提 spec（推荐：所有人）
   - 谁审 spec（推荐：1 个核心维护者 + 1 个使用方）
   - 多久 review 一次全库（推荐：季度 + 大模型升级时）
5. 评审段口头答："spec 库谁审？多久 review？"

## Tips / 提示
- 不强制 git push——截图发到团队群 / 抄到 Confluence 都算
- 反例库（`negative-examples/`）至少要有占位 README，不然回去会忘
- 别建 wiki 凑数（讲师手册反例 #1：wiki 没版本没 review）
- 反例库只加不减是错的（反例 #3）；半年 review 一次必须有"已废除"标签

## Self-Check / 自检
- [ ] 5 目录已在团队承载位置出现（实物或截图）
- [ ] 选定的示例 spec 已就位
- [ ] README 含治理 3 件事（谁提 / 谁审 / 多久 review）
- [ ] 能口头答"spec 库谁审？多久 review？"

## Submission (Counts Toward Capstone) / 提交（计入综合作业）
- 截图或团队文档链接（不强制 git push）
- 一句话："我团队下周第一个要写的 spec 是 ___"

## Negative Examples / 反例
- "建个 wiki 就是 spec 库"（反例 #1）
- spec 写太死（反例 #2）
- 反例库只加不减（反例 #3）
- "团队人少不需要"（反例 #4）
