# D11-01: Walk Through the Spec Library Structure

> Module: D11 AI-Pair Workflow | Credentials: None; MCP demo depends on Day-7 validation

## Purpose
Understand README, decision-cards, implementation, negative-examples, and runbooks. This step turns the module decision into a concrete learner artifact that can be reviewed during class.

## Instructions
- Review the five-directory spec library structure.
- Pick one example spec and adapt it to your team context.
- Write who proposes specs, who reviews them, and how often the library is reviewed.

## Acceptance Criteria
- The requested artifact exists and can be reviewed by the instructor or assistant.
- The artifact uses concrete values from your project rather than generic placeholders.
- Any uncertainty is written explicitly instead of hidden.
- The output remains consistent with earlier decision cards unless you document why the decision changed.

## Submission
- Save the artifact in the matching `submissions/` folder for this step.
- Include short notes, screenshots, logs, or trace links only when they prove the acceptance criteria.

## Common Mistakes
- Calling an unreviewed wiki a spec library.
- Making specs so rigid that AI has no judgment space.
- Letting the negative-example library only grow and never be reviewed.
