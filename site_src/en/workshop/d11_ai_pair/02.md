# D11-2: Read Two Example Specs / D11-2: 示例 spec 阅读 ×2

> 时长：约 10 min ｜ 凭证：讲师发 2 份示例 spec 文件 ｜ 类型：讲

## Background / 背景
两个示例 spec 是你回去能直接裁剪的实物：
- **示例 1：新 agent 上线 spec**（基于 D3 + D5 + D9）
- **示例 2：新 provider 接入 spec**（基于 D4）

讲师 Day-7 准备好完整文件，本子任务你读，并在每份上指出 1 处"如果改成 X 会更好"——这是 D11 验收硬要求。

## What You Need to Do / 你需要做什么
1. 拿讲师发的 2 份示例 spec 文件
2. 逐份过一遍，关注：
   - 示例 1：业务输入 / 必填决策 / 必交产物 / 验收 gate 四段是否齐
   - 示例 2：接口契约 / 必填字段 vs opts 透传规则 / 单测要求 / review checklist
3. 每份上挑出 1 处"如果改成 X 会更好"（可以是更适合你团队的字段、可以是缺的反例引用、可以是过死的约束）
4. 选其中 1 份作为你回去要带走的起点

## Tips / 提示
- spec 不是 SOP——别建议"再加 5 个必填字段"把它写死（反例 #2：过死 spec 让 AI 失判断空间）
- "如果改成 X 会更好"可以是减项，不一定是加项
- 选起点时优先选你团队下周能动的那份

## Self-Check / 自检
- [ ] 两份示例都读过
- [ ] 每份各指出 1 处可改进点
- [ ] 已选定带走的起点 spec

## Submission (Counts Toward Capstone) / 提交（计入综合作业）
- 两处可改进点笔记（一行一处）
- 选定带走的 spec 名 + 一句话"我团队下周怎么开始"

## Negative Examples / 反例
- spec 写太死："必须用 X 模型 + Y temperature"（讲师手册反例 #2）
- 不挑改进点直接收下："示例 = 标准答案"是错的
- 选示例 1 但下周根本不会上线 agent：起点不贴
