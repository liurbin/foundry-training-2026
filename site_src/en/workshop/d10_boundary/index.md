# D10: Foundry Capability Boundary Table

> Module type: reading + discussion | Duration: 60 min | Credentials: None

## Goals
- Map the 14 capability rows to current Foundry boundaries and migration options.
- Identify at least one boundary that affects the learner project.
- Distinguish verified boundaries from unverified assumptions.
- Review consistency with the D1 Foundry fit decision.

## Prerequisites
- D2 through D9 are complete.

## Subtasks
1. [14-Row Capability Domain Overview](01.md) - Mark each domain as used, not used, or uncertain.
2. [Boundary Table Walkthrough](02.md) - Record boundary descriptions and evidence types.
3. [Discuss Three Migration Examples](03.md) - Compare out-of-catalog models, custom control flow, and quota/capacity limits.
4. [Fill Boundary Rows for Your Project](04.md) - Mark all rows and write migration options for hits.

## Acceptance Criteria
- All 14 rows are marked hit or not hit.
- Each hit has a concrete migration or mitigation option.
- Evidence type is known: official docs, portal screenshot, or fork test.

## Credential Notes
None.

## Common Mistakes
- Treating a boundary as a product defect by default.
- Writing switch platform as the only migration option.
- Letting TODO evidence remain in the classroom table.
