# D7-4: Three-Path Orchestration Decision / D7-4: 三路径选型决策

> 时长：约 15 min ｜ 凭证：无 ｜ 类型：评审

## Background / 背景

收尾环节：把主路径跑通经验 + as_tool diff 阅读 + Workflows 录屏，收成一张"三选一"决策卡。三问全答 + 显式拒绝 HandoffService 手写状态机这条已废路径。

## What You Need to Do / 你需要做什么

1. 回答三问（每问选择 + 一句理由）：
   - 编排逻辑稳定 + 不需要自定义控制流？ → Agent Service 原生
   - 编排逻辑要自定义 + 但每个子 agent 独立可测？ → as_tool 模式
   - 复杂分支 / 长时间运行 / 需要 visual designer？ → Workflows
2. 给出综合作业的最终选择 + 理由。
3. 若选 Workflows 或 as_tool → 必须额外回答"为什么不用主路径"。
4. 显式拒绝 HandoffService 反例：写一句"我不会让 AI 给我重写 HandoffService 手写状态机，因为它是 plan v1 旧路径，Agent Service 原生覆盖了 80% 场景"。

## Tips / 提示

- 三问答完后，最终选择必须与答案一致——如果不一致，要么改答案要么改选择，二选一。
- AI-pair 时可能还会推荐 HandoffService（训练数据残留）——必须当场拒掉。
- "我想三种都用" 不是答案——决策卡是逼你选一个。

## Self-Check / 自检

- [ ] 三问全答，每问含选择 + 一句理由
- [ ] 最终选择与三问答案一致
- [ ] 若选 Workflows / as_tool：答出"为什么不用主路径"
- [ ] 显式拒绝 HandoffService 手写状态机（写出来，不是默念）
- [ ] 能口头讲清 as_tool 与主路径的本质差异

## Submission (Counts Toward Capstone) / 提交（计入综合作业）

- 决策卡文件（Markdown）
- 最终选择 + 业务理由
- 显式拒绝 HandoffService 的一句话

## Negative Examples / 反例

- "Workflows 看起来最强大所以选 Workflows" → 反例 1，理由不成立
- "三种都跑通 = 学得好" → 不是；理解边界 > 全跑通（handbook 反例 4）
- AI 推荐 HandoffService 你没拒 → 反例 3，必须显式拒绝
- 三问答案与最终选择矛盾 → 决策卡不算完
