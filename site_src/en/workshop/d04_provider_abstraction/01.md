# D4-1: Provider Interface Design / D4-1: Provider 接口设计

> 时长：约 25 min ｜ 凭证：无 ｜ 类型：练（设计 + 类型定义）

## Background / 背景
- D3 你的业务代码直接依赖 Foundry SDK，本步要把它"剥"出来：抽一层 `ChatProvider` 接口
- 接口设计的好坏决定后两步的复杂度，先想清楚再写
- 参考实现：`workshop/code/mock_provider/provider.py`（同时由另一 agent 产出）

## What You Need to Do / 你需要做什么
1. 在自己的 repo 新建 `chat_provider.py`（或对应语言的接口文件）
2. 用 `Protocol`（Python）或对应语言的接口定义最小集——与 `workshop/code/mock_provider/provider.py` 完全对齐：

   ```python
   from __future__ import annotations
   from dataclasses import dataclass, field
   from typing import Any, Literal, Protocol, runtime_checkable

   Role = Literal["system", "user", "assistant"]

   @dataclass(frozen=True)
   class Message:
       role: Role
       content: str

   @dataclass(frozen=True)
   class Usage:
       prompt_tokens: int
       completion_tokens: int

   @dataclass(frozen=True)
   class ChatResponse:
       content: str
       model: str
       usage: Usage
       raw: dict[str, Any] = field(default_factory=dict)  # provider 原始响应，业务层不读

   @runtime_checkable
   class ChatProvider(Protocol):
       async def chat(
           self,
           messages: list[Message],
           *,
           model: str = "default",
           temperature: float = 0.7,
           max_tokens: int = 512,
           stop: list[str] | None = None,
           **opts: Any,
       ) -> ChatResponse: ...
   ```

   > 最小接口原则：现在只有 `chat()`。需要 embedding 时再加方法 + 测试 + 实现，不准提前加（negative example #1）。

3. 决定**共性字段** vs **opts 透传**：
   - 共性走结构化字段：`temperature` / `max_tokens` / `stop`
   - 专有走 `**opts`：Foundry 的 `thread_id` / OpenAI 的 `tool_choice` 一律不准进接口
4. 写一段 README 解释你的接口为什么这么切（≤200 字）

## Tips / 提示
- 不准"以备将来"塞 Foundry/OpenAI 专有字段；那是 negative example #1
- 不写"抽象工厂的工厂"；单 if/elif 加载 provider 就够
- 参考 `workshop/code/mock_provider/provider.py`（如未完成，按上述结构自己写）

## Self-Check / 自检
- [ ] 接口里没有任何 provider 专有概念
- [ ] 共性字段 vs opts 边界写在 README 里
- [ ] 接口实现 ≤ 2 层抽象
- [ ] 能口头讲清"加第三个 provider 要改哪些文件"（答案应该是"只加一个文件"）

## Negative Examples / 反例
- 接口里塞 `thread_id` "以备将来" —— 第二个 provider 来就得加 if 分支
- 写 4 层抽象（Factory + Builder + Strategy + Registry）—— 你只有 2 个 provider
- "Foundry 支持多 provider 目录所以不用自己抽象" —— 那解决 model_id 切换，不解决 SDK 锁定
