# D4-03: Watch the Foundry to Non-Azure Provider Live Switch

> Module: D4 Provider Abstraction | Credentials: Learners use mock only; instructor uses one non-Azure provider key for the demo

## Purpose
Observe the instructor switch and record differences in response, errors, quotas, or tool semantics. This step turns the module decision into a concrete learner artifact that can be reviewed during class.

## Instructions
- Define the smallest shared provider interface needed by business code.
- Keep provider-specific options behind provider implementations or explicit passthrough fields.
- Use MockProvider to verify the flow without any cloud key.
- Record two behavioral differences from the live-switch demo if this is the observation step.

## Acceptance Criteria
- The requested artifact exists and can be reviewed by the instructor or assistant.
- The artifact uses concrete values from your project rather than generic placeholders.
- Any uncertainty is written explicitly instead of hidden.
- The output remains consistent with earlier decision cards unless you document why the decision changed.

## Submission
- Save the artifact in the matching `submissions/` folder for this step.
- Include short notes, screenshots, logs, or trace links only when they prove the acceptance criteria.

## Common Mistakes
- Leaking provider-specific thread IDs or tool-choice fields into the common interface.
- Building factory-of-factory abstractions for a two-provider exercise.
- Giving learners private provider keys.
