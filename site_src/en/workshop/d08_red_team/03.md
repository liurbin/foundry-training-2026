# D8-3: Fallback When the SDK Run Times Out / D8-3: SDK 跑超时的 fallback

> 时长：约 20 min ｜ 凭证：无需 Azure，本地文件即可 ｜ 类型：练

## Background / 背景
SDK 红队单次 baseline 容易超 50 min 实操窗口（讲师手册"凭证说明"明确"已知坑"）。本子任务的存在就是为了：**你必须当堂产出一份 baseline 报告结构，跑通 SDK 不是前提条件。**

真跑通 SDK 是综合作业加分项 / 课后补，不是本子任务的卡点。

## What You Need to Do / 你需要做什么
1. 用 `workshop/code/sample_red_team/baseline_result.json`（讲师 sample，由另一条流水线产出）作为数据源
   - 这个文件**就是用来给本子任务兜底的**，不强求真跑
2. 把 sample JSON 解析成 baseline 报告结构，必须包含：
   - 总体 ASR 数字（直接取自 JSON）
   - 按攻击类型分类的子 ASR（至少 2-3 类；若 sample 不足 3 类，在报告里说明"覆盖缺口 + 下一步补法"）
   - Top 3 失败 case 列表（case 文本 + 工具判定 + 你的人工初判）
3. 写下你的 SDK 命令 + 配置文件（即便没跑通也要交付，证明你会写）

## Tips / 提示
- 这条路径的产物**结构与真跑 SDK 完全一致**——评分看结构是否齐，不看数字是不是你的
- 报告里要明示"数据来源：sample JSON"，不能伪装成自跑
- 别在 sample 上挑刺说"这数据假"——sample 的目的是练报告骨架

## Self-Check / 自检
- [ ] baseline 报告 4 段齐：总体 ASR / 攻击分类 / Top 3 case / 数据来源声明
- [ ] SDK 命令 + 配置文件已写下（即便未跑通）
- [ ] 若攻击类型 < 3，已在报告里说明缺口

## Submission (Counts Toward Capstone) / 提交（计入综合作业）
- baseline 报告（Markdown 一页内即可）
- SDK 命令 + 配置文件片段
- 明确标注"用 sample JSON 完成"

## Negative Examples / 反例
- 完全跳过这步指望真跑：50 min 内跑不完就交白卷
- 报告里隐瞒数据来源：评分按"造假"处理
- 只交 JSON 不写报告结构：D8 验收要的是报告，不是原始数据
