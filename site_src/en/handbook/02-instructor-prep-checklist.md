# Instructor Day-7 Preparation Checklist

## How to Use
Finish this checklist seven days before training. Any unfinished item needs a fallback before delivery.

## Global Verification
| Status | Item | Evidence |
|--------|------|----------|
| [ ] | Run the adapted fork | Terminal log and failed-item notes |
| [ ] | Validate API drift | Current package versions and changed fields |
| [ ] | Verify portal paths | Screenshots for Models, Agents, Monitoring, Evaluations |
| [ ] | Run workflow samples | Command logs and trace screenshots |
| [ ] | Finalize rubric | One-page scoring rubric |
| [ ] | Confirm spec library | 12 spec files available in the spec library |

## Module Preparation
- D2: decision-card samples and cost examples.
- D3: Bicep template, tracing setup, and API drift notes.
- D4: non-Azure provider key or fallback recording.
- D5: retry stub, load-test recording, cost bands, and capacity explanation.
- D6b: A2A prepared repo, MCP prepared repo, and trace comparison.
- D7: native orchestration trace, as_tool diff, Workflows recording.
- D8: portal red-team screenshots, SDK sample JSON, false-positive notes.
- D9: incident case, runbook template, CI/CD comparison.
- D10: boundary table with evidence per row.
- D11: spec-library demo and MCP or Learn URL fallback workflow.

## Handling Unfinished Items
If something is not live-ready, mark the blocker, prepare a recording or sample artifact, and tell learners which evidence is live and which is fallback.
