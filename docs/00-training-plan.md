# Foundry 开发者培训方案（3 天版）

## 一、培训定位

| 项 | 值 |
|---|---|
| 人群 | 10 人左右 Python 开发者，无 Foundry 经验 |
| 形式 | 远程，全程开摄像头 + 屏幕共享 |
| 深度 | L300（进阶），代码动手为主 |
| 产出 | 每人能独立部署一套 Foundry agent + 接入观测 + 跑红队 + 完成综合作业 |
| 讲师 | 1 主讲 + 1 助教 |
| 时长 | 3 天，每天约 7 小时净时间，留充足 buffer |

## 二、为什么是 3 天而不是 2 天

2 天版评审发现的硬伤：

- 综合作业 45 分钟不可能完成
- Day1 时间表无任何 buffer，Ex01 延迟 10 分钟全天崩
- Ex03 是 workshop 最难的一节，60 分钟动手时间严重不够
- Workflows 补充模块如果再砍就失去意义

放开到 3 天后，所有妥协都不需要做，反而能补充原本缺失的内容（综合实做、案例库、反馈机制）。

## 三、骨架取舍（基于对原 workshop 的核查结论）

### 4 个真实选型案例

| 案例 | 选型 | 理由 |
|------|------|------|
| 企业内部 IT 工单 chatbot | Agent Service | 单一团队、强治理、内置审计 |
| SaaS 产品里的 AI 助手（要支持私有部署） | SDK | 跨云、可移植、客户能自己改 |
| 多 agent 协作的内部研究工具 | SDK + Workflows | 显式编排、需要 checkpoint |
| 一次性 demo / POC | Agent Service | 30 分钟出活，UI 也能改 |

**核心信息**：两条路微软都在推、没合并，**选型看场景**。Ex02 和 Ex03 风格不一样是有意的，本次培训两条都讲。

## 七、远程交付的关键约束

| 项 | 措施 |
|---|---|
| 助教 | 必配 1 人，专门盯聊天区救火 |
| 环境差异 | 强制要求 macOS/Linux/WSL2，Windows 原生不行 |
| 网络 | 提前说明 Azure 中国区不能用，必须国际版订阅 |
| 录屏 | 每个 Ex 提前录 5 分钟"成品演示" |
| 共享文档 | 一份 Google Doc / Notion 实时 Q&A，避免重复回答 |
| 分组 | Day3 综合作业按 3-4 人分组，远程用 breakout room |
| 反馈 | Day1/Day2 末尾各 15 分钟匿名反馈，第二天开场响应 |

## 八、综合作业（Day 3）

### 场景："Zava 客服分诊系统"

重点：**架构选型决策必须有理由**

### 必做（基础分 70%）

1. 用 Foundry Agent Service 创建 1 个"分诊 agent"
2. 用 Agent Framework SDK + Workflows 写 1 个"专家路由"
3. 接入 OTel，能在 Foundry 监控看 trace
4. 跑 1 次红队（`num_objectives=3` 即可）

### 选做加分（30%）

- A2A 暴露专家 agent
- 自定义攻击 prompt
- 设计文档（200 字以内）说明"为什么分诊用 Agent Service、专家用 SDK"

### 评分维度

- 能跑通（40%）
- 架构选型理由（40%）—— **核心，回收开场架构课**
- 观测和评估完整性（20%）

### 节奏

3 人一组，**2.5 小时实做** + 5 分钟演示。

## 九、人类必须做的 gating

🚫 培训日期前至少 2 周必须确认：

- MCAPS 外部订阅是否能开（EMU 不行）
- 每个学员的 Foundry 访问权限
- GPT 模型在订阅区域可用 + TPM 配额 ≥ 50K

🚫 培训日期前 1 周：

- 学员前置准备清单发出
- 一次环境自检（让学员跑 `precheck.sh` 截图给助教）

⚠️ 如果 MCAPS 这关过不去——培训直接黄，没 plan B
