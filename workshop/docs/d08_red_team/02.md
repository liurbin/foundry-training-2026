# D8-2: SDK 红队跑一次

> 时长：约 30 min ｜ 凭证：学员本机 SDK + Foundry 凭证（讲师备共享凭证）｜ 类型：练

## 背景
Portal 跑红队适合探索，但**接 CI/CD 必须走 SDK**——这是 D8 的核心原则之一（讲师手册反例 #4）。本子任务让你在本机跑一次 SDK 红队，验证两条路径产出可对照。

被测 agent 与 portal 那次必须是同一个，attack set 也要尽量一致，这样 ASR 量级才能比。

> **走哪个 Red Teaming Agent**：本课 SDK 走**云端 Foundry Red Teaming Agent**（target 是你的 Foundry agent）。微软另有一个本地 PyRIT-based Red Teaming Agent，**不兼容** Foundry new portal/SDK，本课不用；如果你装错版本会跑不通。讲师手册 D8 "产品口径"段有详细说明。

## 你需要做什么
1. 选定被测 agent：D3 单 agent 或 D6a/D6b 任一
2. 用 SDK 配 attack set（`num_objectives=3` 起步，和 portal 那次对齐）
3. 跑一次 baseline，把输出 JSON 存到本地
4. 在 JSON 里找三件东西并抄下来：
   - 总体 ASR 数字
   - 攻击类型分类清单（至少 2-3 类）
   - 失败 case 列表的前若干条（D8-4 会用到 Top 3）
5. 与 D8-1 抄的 portal ASR 做量级对比

## 提示
- SDK 调用、attack set 配置参数照搬上游 Ex06；本课**不在 SDK 用法上做创新**，只补 CI/CD gate 视角
- 跑 baseline 期间可以并行做 D9 子任务的阅读（讲师会提示）
- 若 50 min 实操窗口内跑不通：**立刻转 D8-3 fallback，不要硬等**

## 自检
- [ ] 本机有一份真跑出来的 JSON 文件（路径自己记住）
- [ ] 知道总体 ASR 数字
- [ ] portal vs SDK 的 ASR 量级一致（差 ≤ 2x 算合理）；不一致能说出可能原因（attack set 不同 / 随机种子 / agent 配置漂移）

## 提交（计入综合作业）
- SDK baseline JSON（真跑出来的）或 D8-3 fallback 产物二选一
- portal vs SDK ASR 对比的一句话结论

## 反例
- 用了不同 agent 或不同 attack set 跑 SDK：两边不可比，等于没跑
- 跑通了不存 JSON：D8-4 分析无源头
- 嫌慢中途 kill 又重启：浪费时间，应该一次跑稳
