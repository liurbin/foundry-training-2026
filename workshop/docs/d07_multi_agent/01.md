# D7-1: 主路径 —— Agent Service 原生

> 时长：约 50 min ｜ 凭证：Foundry 项目 + Agent Service 端点（或讲师共享 / mock） ｜ 类型：练

## 背景

D7 三选一的主路径是 Agent Service 原生编排。你要 AI-pair 生成一个 orchestrator + 两个专家 agent，跑通三段 trace（orchestrator → 专家 1 → 专家 2）。这是 D7 验收的硬门槛——另外两条路径只对照、不要求跑。

## 你需要做什么

1. 用 AI-pair 在 D3 的基础上扩出三个 agent：
   - 1 个 orchestrator（接收用户请求、决定调用谁）
   - 2 个专家 agent（各负责一个子任务）
   - 编排走 Agent Service 原生（不要手写 HandoffService 状态机；那是反例）
2. 跑一次端到端请求，让链路完整走完 orchestrator → 专家 1 → 专家 2。
3. 打开 trace，确认三段都可见，截图归档。
4. 凭证 fallback：
   - 没有 Foundry 端点 → 切讲师共享端点
   - 共享端点也不可用 → 走 mock provider，trace 看讲师截图兜底

## 提示

- AI-pair 时如果它建议"用 HandoffService 自己写状态机"——拒掉，告诉它走 Agent Service 原生。
- 编排逻辑越简单越好：本步目标是"trace 三段完整"，不是"编排有多聪明"。
- 跑不通别跳 as_tool（D7-2）——先在主路径 debug 到通，跳来跳去 = 一种都没学透（handbook 反例 2）。

## 自检

- [ ] orchestrator + 2 个专家 agent 都创建出来
- [ ] 端到端请求能跑完
- [ ] trace 里能看到三段：orchestrator → 专家 1 → 专家 2
- [ ] 编排走 Agent Service 原生，没有手写 HandoffService
- [ ] 跑不通的情况下：记录卡点 + 看讲师演示 trace

## 提交（计入综合作业）

- 三个 agent 的代码目录
- trace 三段截图
- 若没跑通：卡点记录 + 讲师演示 trace 截图

## 反例

- 重写 HandoffService 手写状态机 → plan v1 旧路径已废，必须显式拒绝（handbook 反例 3）
- 主路径跑不通就跳到 as_tool → 跳来跳去 = 一种都没学透
- "三种都跑通 = 学得好" → 不是；理解边界 > 全部跑通
