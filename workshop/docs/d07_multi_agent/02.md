# D7-2: 对照路径 A —— as_tool

> 时长：约 20 min ｜ 凭证：本机即可（apply diff，不需要额外端点） ｜ 类型：练

## 背景

as_tool 是"把每个子 agent 包成 tool，让 orchestrator 当 tool 调用"的模式。本步不要求跑通，要求你 apply 讲师 prepared diff，看清它与主路径的本质差异：控制流归谁、可测性怎么变、状态在哪里。

## 你需要做什么

1. 从讲师准备清单拿到 as_tool 模式的 prepared diff（patch 文件）。
2. 在 D7-1 主路径代码上 `git apply` 这个 diff（或新开分支 apply）。
3. 读 diff，回答三个问题（每个 1-2 句）：
   - 控制流：谁决定下一步调谁？主路径 vs as_tool 各在哪一层？
   - 可测性：哪个模式更容易给单个专家 agent 写单测？为什么？
   - 状态归属：会话状态、中间结果各自存在哪里？
4. 不要求实际跑通；能读懂 diff、能口头讲清差异即可。

## 提示

- as_tool 把"编排"显式化到 orchestrator 的代码里——这是它和主路径最大的差异。
- "主路径让 Agent Service 黑盒编排" vs "as_tool 让你自己写编排"——这一对照是决策卡的关键输入。
- 不准说"这俩差不多"——说明你 diff 没读透。

## 自检

- [ ] prepared diff 成功 apply（或在新分支可见）
- [ ] 能口头讲清控制流的差异（谁决定下一步）
- [ ] 能口头讲清可测性的差异
- [ ] 能口头讲清状态归属的差异
- [ ] 没有把"as_tool 跑起来"误当成本步目标

## 提交（计入综合作业）

- apply 后的分支或 patch 文件路径
- 三个问题的回答（200 字以内）

## 反例

- "as_tool 和主路径差不多" → diff 没读透
- 跑不通 as_tool 就觉得失败 → 本步不要求跑
- 用 as_tool 替代主路径作为综合作业默认选项 → 必须答出"为什么不用主路径"
