# D5-4: 压测脚本观看

> 时长：约 15 min ｜ 凭证：无（讲师跑，学员观看，避免打爆共享配额）｜ 类型：讲师演示 + 学员观察记录

## 背景
- 100 RPS × 5min 真实压测由讲师一次性演示，学员**只看不跑**
- 学员侧跑会触发共享配额 + 真实账单 —— D5 spec 明示禁止
- 压测脚本放在 `workshop/code/load_test/`（由另一 agent 同期产出）

## 你需要做什么
1. 看讲师跑 `workshop/code/load_test/` 下的压测脚本，核心命令大致是：

   ```bash
   # 方式 A：调脚本
   bash workshop/code/load_test/run.sh

   # 方式 B：直接调 Python（带参数）
   python3 workshop/code/load_test/loadtest.py --url <演示端点> --qps 100 --duration 300 --concurrency 50
   ```

2. 你的任务：在自己笔记里记 **2 个观察点**：
   - 观察点 1（retry）：429 出现时，多副本退避是否真的"错峰"？（看 retry 触发时间分布，是否有 jitter 的痕迹）
   - 观察点 2（cache）：随时间推移，缓存命中率曲线是否上升？（命中率从 0 → X% 的爬升说明 cache 真的接进去了）
3. 如果讲师 portal 共享，看 Monitoring → Live metrics，留意 p95 延迟变化
4. 写一段 100 字观察笔记，含上面两点 + 一个 D5 知识点的印证

## 提示
- 你不会拿到压测脚本运行权限，看就行；想自己跑请课后用 stub_429
- 观察"错峰"不是看精确秒数，是看 retry 时间散点是否分散
- 命中率不上升说明 cache 接错了或 TTL 太短

## 自检
- [ ] 记录 retry 触发是否有 jitter 错峰（1 句结论）
- [ ] 记录缓存命中率是否随时间上升（1 句结论）
- [ ] 能口头说出"如果我自己跑这个压测会发生什么"（提示：打爆共享配额 + 自付账单）

## 提交（计入综合作业）
- 产物：`load_test_notes.md`（含上面两点观察 + 100 字笔记）
- 放：`submissions/d5_4_load_test/load_test_notes.md`

## 反例
- 学员自己偷跑 100 RPS —— 打爆共享配额，影响别人，且产生真实账单
- 只记"看到压测了"，不记 retry/cache 观察点 —— 等于没看
- 因为没真跑就觉得"D5 学得不实在" —— 真跑的代价由讲师承担，你拿走的是观察能力
