# D5-3: 成本三档估算 + 容量模式承接

> 时长：约 25 min ｜ 凭证：无 ｜ 类型：练（脚本 + 表）

## 背景
- 用 D2 的成本估算输入（DAU / token / QPS）+ D5-0 的容量模式选择跑出 1k / 10k / 100k DAU 三档月度 $
- 不只是模型费 —— 运行时（Hosted Agents 计费 / ACA 容器费）+ 出口流量 + Application Insights 摄入费一起算
- best/worst 区间差距 ≤ 3x，否则你的假设太松
- **每档要明确：用哪种容量模式**（PAYG / quota increase / PTU / reservation）——同一项目不同档可以选不同容量模式（如 1k DAU 用 PAYG，100k DAU 上 PTU）

> 主路径 = Hosted Agents + PAYG（默认）；其他组合按 D5-0 decision note 选定。下面脚本里的 `container_cost` 既可代表 Hosted Agents 的运行时费，也可代表 ACA 的容器底线费——按部署目标选一种，并在"假设清单"里写明。

## 你需要做什么
1. 写一个估算脚本 `estimate_cost.py`（或电子表也行），输入 DAU + 平均 token + **容量模式**，输出三档：

   ```python
   def estimate(dau, capacity_mode="payg", in_tok=500, out_tok=300, cache_hit_rate=0.3):
       req_per_month = dau * 30 * REQ_PER_USER
       effective = req_per_month * (1 - cache_hit_rate)
       if capacity_mode == "payg":
           model_cost = effective * (in_tok * IN_PRICE_PAYG + out_tok * OUT_PRICE_PAYG)
       elif capacity_mode == "ptu":
           # PTU 按月固定费 + 超出部分回落 PAYG；这里用月固定费近似
           model_cost = PTU_MONTHLY_FIXED  # 学员按 D5-0 选的 PTU 单位数估
       elif capacity_mode == "reservation":
           # Reservation 是 commitment 折扣，叠加在 PTU 或 PAYG 上
           model_cost = effective * (in_tok * IN_PRICE_PAYG + out_tok * OUT_PRICE_PAYG) * (1 - RESERVATION_DISCOUNT)
       container_cost = RUNTIME_COST_FIXED  # Hosted Agents 运行时费 / ACA min replicas ≥ 1 底线（按部署目标选口径）
       insights_cost = req_per_month * INSIGHTS_PER_REQ
       return {
           "capacity_mode": capacity_mode,
           "model": model_cost,
           "container": container_cost,
           "insights": insights_cost,
           "total": model_cost + container_cost + insights_cost,
       }
   ```

2. 跑三档：1k / 10k / 100k DAU，每档给 best/worst（cache 命中率取 D5-2 实测值的 ±20%）+ 容量模式
3. 输出表：

   ```markdown
   | DAU | 容量模式 | best $/月 | worst $/月 | 主导成本项 |
   |-----|---------|----------|-----------|-----------|
   | 1k  | PAYG | | | |
   | 10k | PAYG / quota increase | | | |
   | 100k| PTU（如选） | | | |
   ```

4. 与 D1 prep 时确认的 TPM/RPM 配额对照：哪一档会超 PAYG 默认配额、什么时候需要升级到 quota increase 或 PTU
5. 回答："如果 DAU 翻 10 倍，哪一项成本先爆？容量模式要不要换？"

## 提示
- 漏算 runtime（Hosted Agents 计费 / ACA 容器费）/ insights 是常见错；这两项中型项目能占 30%+
- best/worst 差 ≤ 3x，否则就是"假设差不多"；不接受
- 若部署目标是 **Hosted Agents**：scale-to-zero 是产品默认，运行时费按 Hosted Agents 计费模型算
- 若部署目标是 **ACA 自托管**：min replicas 必 ≥ 1（D5 spec 硬约束），容器底线成本不为 0
- **容量模式跨档可变**：1k DAU 用 PAYG 完全合理；100k DAU 若选 PTU 要算 PTU 单位数（≥ 一档起买）+ 区域/模型支持
- 反过来：所有三档都填同一种容量模式也可以，但要在"假设清单"写明"为什么不需要切换"

## 反例
- 成本只算模型费 —— 漏算 runtime / 出口 / Insights，30%+ 偏差
- best/worst 差 10x —— 假设太松，等于没估
- 单点数字没区间 —— 不接受
- 三档都填 PAYG 但 100k DAU 时 PAYG 已超默认配额 —— 没承接 quota increase / PTU 升级路径
- 把 Hosted Agents 当 ACA 写一份 min-replicas-≥1 的 Bicep —— 路径选错（讲师手册 D5 反例 #1）
- ACA 路径 min replicas 写 0 "省钱" —— 冷启动 + 第一次 429 同时炸（讲师手册 D5 反例 #2）
