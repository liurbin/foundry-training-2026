# D6a-1: SDK 路径重写 D3 agent

> 时长：约 15 min ｜ 凭证：mock provider，本机即可 ｜ 类型：练

## 背景

D3 你已经用 Agent Service 跑通一个单 agent。本步要用 Agent Framework SDK 把同一段业务逻辑再实现一遍，作为后面"对比表 + 决策卡"的对照基线。这里只关心"跑得起来 + 输入输出一致"，不评判哪条路径更好。

## 你需要做什么

1. 在 D3 仓库外新建一个目录（或同仓 `sdk/` 子目录），用 Agent Framework SDK 重写 D3 的 agent；business logic 保持不变。
2. provider 走 mock：不连真实 Foundry / OpenAI 端点，本机可跑即可。
3. 给一次 D3 用过的输入，确认 SDK 路径输出与 Agent Service 路径在业务含义上等价（不要求逐字节相同）。
4. 留一个 `README.md` 记录启动方式（命令行、依赖、入口文件）。

## 提示

- 不准把 Agent Service 的代码复制改名——必须按 SDK 自己的 API 重写。
- provider 抽象沿用 D4 的接口，不要直接 `import openai`（那是 D6a 反例 3，留到第二次 vendor 锁定的坑）。
- mock provider 可以是固定字符串或基于输入的简单函数，只要走得通 SDK 的 message / tool 调用回路即可。

## 自检

- [ ] SDK 路径 agent 在 mock provider 下能从输入产生输出
- [ ] 业务输出与 D3 Agent Service 路径在含义上等价
- [ ] 启动方式在 README 写清（命令 + 依赖 + 入口）
- [ ] 没有 `import openai` 这类绕过 D4 抽象的写法

## 提交（计入综合作业）

- SDK 路径 agent 的代码目录路径
- 一次"输入 → 输出"的运行截图或日志片段
- README 中的启动说明

## 反例

- 把 Agent Service 代码复制一份、改个名字交差 → 没有重写就没有对比
- 直接 `import openai` 调真实端点 → 跳过 D4 provider 抽象，埋第二次 vendor 锁定
- "跑不起来但代码看起来对" → 没跑通不算
