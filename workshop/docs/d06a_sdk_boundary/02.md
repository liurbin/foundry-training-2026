# D6a-2: 代码量 / 依赖 / 启动方式对比表

> 时长：约 10 min ｜ 凭证：无 ｜ 类型：练

## 背景

跑通两条路径只是素材，真正进入决策卡的输入是"在哪些维度上不一样"。本步把 D6a-1 的 SDK 路径与 D3 的 Agent Service 路径放到一张表里，至少 4 行，逼自己写出差异而不是"差不多一样"。

## 你需要做什么

1. 新建一个对比表（Markdown 表格即可，放在 D6a-1 的 README 或单独 `compare.md`）。
2. 至少 4 行，每行一个维度，给出两条路径各自的具体取值（数字 / 字符串 / "无"），不允许写"差不多"。
3. 建议维度（至少覆盖 4 项）：
   - 代码量（业务文件行数，排除 boilerplate）
   - 依赖数（直接依赖包，不含传递依赖）
   - 启动方式（托管 / 自己起进程 / 命令）
   - 运行时位置（Foundry 托管 / Container Apps / 本机）
   - 状态存储（Service 自带 / 自建 Redis / Cosmos / 无）
   - 观测接入方式（portal trace / 自接 App Insights / 无）

## 提示

- 数字栏写真实数字（用 `wc -l` 或行计数），不靠估算。
- "差不多一样"是触发反例的信号——如果真差不多，说明你选错了对比维度，换一个。
- 这张表是 D6a-3 决策卡的输入，写得糙后面会反工。

## 自检

- [ ] 表格 ≥ 4 行，每行两侧都有具体取值
- [ ] 没有任何一格写"差不多"或"类似"
- [ ] 数字栏有真实数字来源（命令或文件）
- [ ] 至少覆盖：代码量、依赖、启动方式、运行时位置 四项中的任意 4 项

## 提交（计入综合作业）

- 对比表文件路径
- 对比表本体（贴进综合作业归档目录）

## 反例

- "两边代码差不多" → 不接受，重写
- 维度只写概念不写值（例："观测：都能接" → 没说怎么接、谁付钱）
- 数字靠目测 → 用工具数
