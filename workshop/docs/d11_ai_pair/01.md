# D11-1: spec 库结构走读

> 时长：约 8 min ｜ 凭证：讲师投屏 demo 仓库 ｜ 类型：讲

## 背景
D11 的核心命题：AI-pair 不能停留在个人小聪明，要团队资产化。最低门槛是一套 spec 库。本子任务先把推荐目录结构过一遍，让你能回去抄。

5 个目录：`README.md` / `decision-cards/` / `implementation/` / `negative-examples/` / `runbooks/`。

## 你需要做什么
1. 跟讲师投屏，看一遍 demo 仓库的 5 个目录
2. 在笔记里记下每个目录的用途（不超过一行）：
   - README.md：本库怎么用 / 怎么贡献 / 怎么 review
   - decision-cards/：决策卡模板（D1/D2/D6a/D7/D10 产物）
   - implementation/：实现 spec（D3/D4/D5/D6b/D8/D9 产物）
   - negative-examples/：反例库（持续更新）
   - runbooks/：D9 runbook 模板
3. 标记你团队"已有 / 部分 / 没有"的目录——D11-4 抄回去时用得上

## 提示
- 不要纠结目录名称（你团队叫 `playbooks` 也行）——记住的是 5 个用途
- "1-2 人团队不需要 spec 库"是反例（讲师手册反例 #4）
- 别建 wiki 凑数（反例 #1：wiki 没版本没 review，半年腐烂）

## 自检
- [ ] 能复述 5 个目录的用途
- [ ] 标记完自己团队已有 / 没有

## 提交（计入综合作业）
- 5 个目录用途笔记 + 自己团队现状标记

## 反例
- "建个 wiki 就是 spec 库"（反例 #1）
- "团队人少不需要 spec 库"（反例 #4）
