# D4-2: MockProvider 实现 + 业务代码改造

> 时长：约 35 min ｜ 凭证：无（这是 D4 的设计目标） ｜ 类型：实操

## 背景
- 第 1 步定义了接口，本步实现 MockProvider，并把 D3 的 agent 调用切到接口背后
- 学员侧用 MockProvider 跑通，**不需要任何 Azure 凭证**
- FoundryProvider 实现保留（不删 D3 代码），但业务层不再直接 import 它

## 你需要做什么
1. 写 `MockProvider`（参考 `workshop/code/mock_provider/provider.py`）：

   ```python
   class MockProvider:
       async def chat(self, messages, **opts):
           # 返回写死文本，能让 abstraction 跑起来即可
           return ChatResponse(
               content="[mock] hello from MockProvider",
               usage={"input_tokens": 0, "output_tokens": 0},
           )
   ```

2. 写 `FoundryProvider`：把 D3 的 agent_reference 调用代码搬进来，包成 `chat()` 方法
3. 写 switch 加载（单 if/elif）：

   ```python
   def load_provider() -> ChatProvider:
       name = os.getenv("PROVIDER", "mock")
       if name == "mock":
           return MockProvider()
       elif name == "foundry":
           return FoundryProvider()
       raise ValueError(f"unknown provider: {name}")
   ```

4. 改造业务代码：之前 `from azure.ai... import` 全删，改成 `provider = load_provider()` + `provider.chat(...)`
5. 跑测试（参考 `workshop/code/mock_provider/test_provider.py`）：

   ```bash
   PROVIDER=mock python -m pytest tests/
   ```

6. 在断网 / 无 key 环境跑一遍业务流程，确认 MockProvider 真的能撑起来

## 提示
- MockProvider 不要写得太聪明（带状态、模拟错误）；那是单测 fixture，不是 provider
- 业务代码 `grep -r "azure\|openai" src/`（排除 provider 实现文件）应当为空
- 如果你 grep 还有命中，先看是不是 type hint 没改干净

## 自检

- [ ] MockProvider 在断网环境能跑通业务主流程
