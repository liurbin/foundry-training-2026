# D9-3: 事故复盘案例阅读

> 时长：约 15 min ｜ 凭证：讲师发脱敏材料，不联网 ｜ 类型：讲

## 背景
runbook 模板填写之前先读真案例。讲师会发一份脱敏过的事故复盘（5 段 timeline），你只需要识别"哪一步如果当时有 runbook 就不会炸"——这是 D9-4 写 runbook 的入门动力。

## 你需要做什么
1. 拿到讲师发的脱敏复盘材料（线下纸质或 Markdown）
2. 通读 5 段 timeline（事件触发 → 发现 → 定位 → 处置 → 复盘）
3. 在每段旁标注：
   - 这一步耗时多久（材料里有时间戳）
   - 这一步如果有 X 是否能更快（X 可以是 runbook / alert / 监控 / 回滚命令 / 别的）
4. 圈出"最值得做 runbook"的那一步，记下来 D9-4 用

## 提示
- 不要联网搜原案例（讲师特意脱敏）
- 不要争论"这家公司为什么这么搞"——专注 timeline 上的可改进点
- 5 段都该有标注，不要只标看起来戏剧化的那一段

## 自检
- [ ] 5 段 timeline 每段都有"如果当时有 X 就不会炸"的标注
- [ ] 已圈出最值得做 runbook 的 1 步
- [ ] 能口头讲清"这次事故如果有 runbook，恢复时间能从 N 降到 M"

## 提交（计入综合作业）
- timeline 标注笔记
- 一句话总结："这次事故最关键的 runbook 缺口是 ___"

## 反例
- "我们项目不会出这种事"：跳过 = 复刻（讲师手册反例 #4）
- 只看戏剧化的高潮段：忽略了真正可改进的处置/定位段
- 标注全是"加强监控"：空话（D9 验收明令不接受）
