# D9-6: 生产化 checklist 应用清单

> 时长：约 20 min ｜ 凭证：D9 spec checklist 模板（讲师 Day3 上午统一发）｜ 类型：评审

## 背景
D9 收口产物——把 spec-d9 的 checklist 每一项对到你项目当前状态，留下"已有 / 部分 / 没有"的判定 + 没有的项给最小补法。**全没有 = 生产化预备状态，不阻塞**；这是 v2 明示的口径，避免项目尚早的学员被卡。

## 你需要做什么
1. 拿讲师发的 `spec-d9-prod-checklist.md` checklist 模板（事故 / 回滚 / 监控 / 成本 / CI/CD 五段共十余项）
2. 对每一项打勾 + 写判定：
   - **已有**：直接引用证据（仓库路径 / 工单 / 截图）
   - **部分**：说"已有 X，缺 Y"
   - **没有**：给最小补法（**不超过 1 周工作量**，不接受"加强监控"这种空话）
3. 整合本模块前面的产出：
   - D9-2 红队 gate 草稿（接进 CI/CD 段）
   - D9-4 runbook 一份（接进事故 / 回滚段）
   - D9-5 平台选择 + 理由（接进 CI/CD 段）
4. 在清单尾部写一行总结："我项目离生产化还差 N 项，最关键的是 ___"

## 提示
- 若你项目所有项都判"没有"——**这是合理状态**，按"生产化预备"标记即可，评审段不阻塞
- 监控阈值必须从 SLO 反推，不接受拍脑袋数字
- 别让 AI 帮你写"以后补"（讲师手册 D9 spec → 约束段）

## 自检
- [ ] checklist 所有项都判定（不留空）
- [ ] 没有 / 部分的项都有具体补法（≤ 1 周工作量）
- [ ] 能口头答："如果今晚 alert 触发，谁接？怎么响应？"
- [ ] 能指出红队 gate 在 pipeline 的接入位置（PR check / pre-deploy / post-deploy 三选）
- [ ] 全没有的学员：在清单尾部明示"生产化预备状态"

## 提交（计入综合作业）
- 填好的 checklist 应用清单（Markdown）
- 总结一句话

## 反例
- 留空项："以后再判"（讲师手册 spec → 约束段明令禁止）
- 补法写"加强监控"：空话（D9 验收明令）
- "我们 startup 不需要"（讲师手册反例 #1）：反了，startup 一个事故就死
- alert 接 noreply / 无人盯频道（反例 #2）
- trace 采样 100% 觉得"安全"（反例 #3）
