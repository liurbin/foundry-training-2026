# D9-4: runbook 模板填写

> 时长：约 15 min ｜ 凭证：讲师发 runbook 模板（Markdown）｜ 类型：练

## 背景
runbook 在事故发生时再写就晚了——D9 验收硬要求"至少 1 条具体事故场景的处置流程"。本子任务用讲师模板填 1 个场景，目标是"如果今晚 alert 触发，能照着这份跑下来"。

场景来源优先用 D9-3 圈出的那一步；如果觉得不贴自己项目，可换成自己项目能想到的最可能事故。

## 你需要做什么
1. 拿讲师 runbook 模板（Markdown）
2. 选 1 个具体事故场景（例：模型限流爆 429 / 成本超日预算 / agent hang / Bicep apply 失败回不去）
3. 填齐四段：
   - **触发**：什么 alert / 什么现象 / 谁先看到
   - **谁响应**：on-call 角色名（不是人名）、备份联系方式
   - **怎么定位**：前 3 个该看的面板 / 日志查询 / 必跑的诊断命令
   - **怎么回滚**：上一次 deploy 的回滚命令一行 + 验证回滚生效的方法
4. 自测："如果今晚 03:00 alert 响，照这份能跑下来吗？"

## 提示
- 一行回滚命令要能现在就在终端复制粘贴跑（讲师手册反例 #4）
- "谁响应"写角色不写人名（避免离职即失效）
- 回滚单元要明确（agent 版本？Bicep stack？模型版本？三个层级别混）

## 自检
- [ ] 4 段全填 + 不留空
- [ ] 回滚命令是具体可执行的一行（不是"参考 wiki XX"）
- [ ] 能口头答："如果今晚 alert 触发，谁接？怎么响应？"

## 提交（计入综合作业）
- 填好的 runbook 一份（Markdown）
- 一句话场景描述（写在 runbook 顶部）

## 反例
- "回滚命令以后写"（讲师手册反例 #4）：deploy 之前就要有
- "谁响应"写成人名"张三"：人一离职就死
- "怎么定位"写"先看监控"：等于没写
