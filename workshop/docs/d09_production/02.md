# D9-2: 红队 gate 接入

> 时长：约 15 min ｜ 凭证：D8 baseline 产物 + D9-1 走查笔记 ｜ 类型：练

## 背景
红队 baseline 不接进 pipeline 就只是一次性活动——这是 D8 的核心原则之一。本子任务把 D8 产出的 SDK baseline 命令挂到 D9-1 走查过的 workflow 上，**设计稿层级**即可，不要求真跑。

## 你需要做什么
1. 在 D9-1 标注的"红队 gate 待接入位置"上，写一段 yaml step 草稿，调用 D8 的 SDK baseline 命令
2. 选定 gate 位置（三选一，写出理由）：
   - PR check（PR 触发即跑，慢但拦截早）
   - pre-deploy（merge 后部署前跑，常见折中）
   - post-deploy（部署到 staging 后跑，对 prod 流量无影响）
3. 填 3 条 gate 规则（来自讲师手册 spec 的模板）：
   - gate A：ASR > X% 阻塞 merge（X 来自 D8-4 的业务阈值）
   - gate B：新增攻击类型失败率 > Y% 报警
   - gate C：自定义（如：成本超 Z 触发跳过，或某类高 false positive 攻击降权）
4. 如果用 Azure DevOps（D9-5 决定），写出等价 task 名

## 提示
- gate 不要求真跑通；评分看设计稿是否能落地
- 阈值必须和 D8-4 业务可接受 ASR 一致，不接受"先填个 5%"
- 草稿可以 commented out 方式提交，明示"待 D8 真跑通后启用"

## 自检
- [ ] yaml step 草稿已写（call SDK baseline + 解析 ASR + fail/pass 判定）
- [ ] gate 位置三选一已定 + 有理由
- [ ] 3 条 gate 规则全填、阈值与 D8-4 一致

## 提交（计入综合作业）
- yaml step 草稿
- gate 位置选择 + 理由
- 3 条 gate 规则表（含阈值）

## 反例
- gate 阈值拍脑袋（如固定 5%）：与业务可接受 ASR 脱钩（D8 子 rubric 失分）
- 只挂 PR check 不考虑跑得慢：阻塞所有 PR，团队会绕过
- 3 条 gate 规则填 1 条就交：未达 D8 子 rubric 验收
