# D10-4: 给自己的项目填一行边界

> 时长：约 15 min ｜ 凭证：边界表 + D1 决策卡 ｜ 类型：练 + 评审

## 背景
D10 收口产物——你要在 13 行边界表上对自己项目逐行勾选命中、为命中项写出迁移方案、并与 D1 决策卡做一致性自检。

**口径再次强调**：边界表"验证来源"三选一硬要求（官方文档 URL / portal 截图 / fork 实测）；"未验证假设"只能列脚注、不进入主表。命中判定要建立在主表的已验证边界上。

## 你需要做什么
1. 拿到边界表实物（讲师 Day-7 定稿）+ 你的 D1 决策卡
2. 在边界表 13 行上**全部判定**："命中 / 未命中"
3. 命中项每条写：
   - 命中的具体业务场景（不超过两行）
   - 迁移方案（用 D10-3 的"绕过 / 混合 / 切走"三选 + 你选哪个 + 理由）
4. 与 D1 决策卡做一致性自检：
   - 若 D1 说"用 Foundry"但 D10 命中 ≥ 3 项关键边界——**回去 review D1**，在 D1 上加备注
   - 若一致，明示"D1 决策仍然成立"
5. 评审段口头答："命中的边界里，哪一项 6 个月内最可能成为阻塞"

## 提示
- 通常学员至少有 1-2 项命中或部分命中（讲师手册反例 #4）——0 项往往是没认真对照
- 没命中的项不要硬找（讲师手册 spec → 约束段）
- 命中 + 业务暂未触发 = 记 risk register，不一定立刻动

## 自检
- [ ] 13 行全判定（不留空）
- [ ] 命中项都有具体迁移方案 + 理由（不接受"考虑切到其他平台"）
- [ ] 与 D1 决策卡一致性自检完成（写明一致 or 需回去 review）
- [ ] 能口头答"6 个月内最可能阻塞的命中项"

## 提交（计入综合作业）
- 学员自填的边界表（一份 Markdown 表）
- D1 一致性自检结论（一行）

## 反例
- "我项目没命中任何边界"（讲师手册反例 #4）：通常是没认真对
- "Foundry 这些都不能做所以不用 Foundry"（反例 #1）：边界 ≠ 否决
- 迁移方案空话（"考虑切到其他平台"）：验收 checklist 明令不接受
- 命中边界 = 立刻迁移（反例 #3）
