# D10-3: 3 个迁移方案样本讨论

> 时长：约 15 min ｜ 凭证：纯讨论 ｜ 类型：讲 + 评审

## 背景
迁移方案最容易写空（"考虑切到其他平台"——讲师手册反例 #2、验收 checklist）。本子任务用 3 个常见命中场景做样本，让你看到"具体迁移方案"长什么样，避免 D10-4 自己写时写空。

三个样本覆盖：
- Models 目录外：用了 Foundry 不直接支持的模型
- Agent Service 自定义控制流：复杂状态机受限
- Quotas / Cost：TPM / RPM 配额上限挡住业务高峰

## 你需要做什么
1. 跟讲师走完 3 个样本，每个样本听完做笔记：
   - 命中的具体场景（业务长什么样）
   - 迁移方案 A：绕过（如：用 Foundry 包一层 + 直连 OpenAI / Azure OpenAI）
   - 迁移方案 B：混合（如：边界场景走 SDK + 其他走 Service）
   - **不只有"切走"**——讲师手册反例 #2
2. 在每个样本里选你觉得对自己项目最有借鉴的那一条记下
3. 准备 D10-4 自己项目命中时，套同样的"绕过 / 混合 / 切走"三选

## 提示
- 迁移方案应当具体到"用什么代替 + 改动范围"
- "切走"不是错答案，但要有理由（命中数 + 业务紧迫度 + 切换成本）
- 命中 + 业务暂未触发 = 记录在 risk register，不一定立刻动（讲师手册反例 #3）

## 自检
- [ ] 3 个样本每个都能复述命中场景 + ≥ 1 个具体迁移方案
- [ ] 能识别"绕过 / 混合 / 切走"的区别
- [ ] 知道为什么"切走"不该是默认答案

## 提交（计入综合作业）
- 3 个样本各记 1 个最有借鉴的迁移方案（一行即可）

## 反例
- 迁移方案全填"切到其他平台"（讲师手册反例 #2 + 验收 checklist）
- 命中就立刻迁移（反例 #3）
- 边界 = 否决（反例 #1）
