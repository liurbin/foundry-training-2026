# D10-2: 边界表实物走读

> 时长：约 20 min ｜ 凭证：纯阅读，无 Azure ｜ 类型：讲

## 背景
讲师 Day-7 已经把 14 行边界表的"验证来源"列填实——**官方文档 URL / portal 截图 / fork 实测**三选一是硬要求。本子任务让你过一遍实物，重点是建立"边界结论必须有可验证来源"的肌肉记忆。

**"未验证假设"口径**：只能作为风险备注列在边界表脚注，**不进入主表、不作为课堂边界结论**。你在主表上看到任何 "TODO" 都应当现场反馈给讲师。

## 你需要做什么
1. 跟讲师走完 14 行边界表实物（投屏）
2. 每行做三件事：
   - 看"当前边界"列写了什么（不能做 / 有限制）
   - 看"验证来源"列是哪一种（URL / 截图 / fork 实测）
   - 在自己笔记里抄下你最关心的 ≤ 3 行的边界描述 + 来源
3. 若主表里看到 "TODO" 没替换为三选一来源——**举手反馈**

## 提示
- 来源是 URL 的，记下能直接点开
- 来源是 portal 截图的，记下截图大致内容（学员侧不必拿到截图原图）
- 来源是 fork 实测的，记下讲师跑的什么用例
- 别把"我听某某说"当来源——这是 negative example #4 的源头

## 自检
- [ ] 知道自己 ≤ 3 行关心项的边界描述 + 验证来源
- [ ] 能区分"边界已验证"vs"未验证假设"
- [ ] 若看到 TODO 已反馈

## 提交（计入综合作业）
- 关心的 ≤ 3 行的边界 + 来源笔记（D10-4 会用）

## 反例
- 把脚注的"未验证假设"当主表结论：违反 D10 硬要求
- 不看来源只看结论："这家说不能做" = 听小道消息
- TODO 没反馈：边界表后续无法迭代
