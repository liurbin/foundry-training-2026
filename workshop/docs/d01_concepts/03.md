# D1-3: 评审与反例对照

> 时长：约 15 min ｜ 凭证：无 ｜ 类型：评审

## 背景
- D1 没有代码评审，评审的是"决策卡的合理性"
- 讲师会抽 2-3 份决策卡公开点评，你即使没被抽到，也要拿这 4 条反例对照自己卡
- 这步过后你才"算完成 D1"

## 你需要做什么
1. 把第 2 步的决策卡放在屏幕上
2. 对照下面 4 条 negative example 自检：
   - 反例 1：客户合同 ≠ 技术选型 —— 你的结论是不是只因"我们是 Azure 客户"？
   - 反例 2：托管平台 vs 编排库不可比 —— 你有没有写"Foundry 比 LangGraph 高级"？
   - 反例 3：迁移成本不在"以后" —— 结论里是否藏着"先不用，以后再迁"？
   - 反例 4：Foundry ≠ 锁死 Azure —— 你有没有把"锁定担忧"误用为"不用 Foundry"的理由？
3. 若命中任意一条，回去改决策卡（结论或不确定栏）
4. 准备口头回答："为什么不选 LangGraph / 不直接 Azure OpenAI"中至少一条

## 提示
- 反例命中不丢人，没修反而丢分
- 口头回答不需要全对，要的是"你想过这条对照"
- 评审段被抽到时，先讲"我不确定的地方"那一栏，比讲结论得分高

## 自检
- [ ] 4 条反例每条都过了一遍，命中的已改
- [ ] 能 30 秒讲清"为什么不选 LangGraph"或"为什么不直接用 Azure OpenAI"
- [ ] 决策卡里没有"再想想 / 看情况 / 视后续而定"这类话

## 提交（计入综合作业）
- 产物：评审后修订版决策卡（覆盖第 2 步的文件即可）+ 一段 50 字"评审后我改了什么"备注
- 放：`submissions/d1_3_review/decision_card_v2.md` + `notes.md`

- 上面 4 条本身就是本步要对照的反例
