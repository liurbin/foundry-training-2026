# D6b-1: MCP 是什么、与 tool calling 的区别

> 时长：约 10 min ｜ 凭证：无 ｜ 类型：讲

## 背景

很多人把 MCP 当成"tool calling 的另一种写法"——这是错的。MCP 是**跨进程**的 tool/resource 协议，agent 和 tool 在不同进程里，靠协议通信；tool calling 是 prompt 里塞一段 function schema，让模型在同一次推理里产出调用。这两个的成本结构、运维负担、复用边界完全不同。本步只要求你能讲清边界，不写代码。

## 你需要做什么

1. 用自己的话写 2-3 句，回答：MCP 与 tool calling 的本质区别是什么？（关键词：进程边界、协议 vs schema、谁负责生命周期）
2. 列 1 个"应该用 MCP 而不是 tool calling"的场景（提示：跨 agent / 跨语言 / 已有外部服务想被多个 agent 共享）。
3. 列 1 个"包成 MCP 反而是自己加运维负担"的场景（提示：纯本地函数、只有自己用、没有跨进程需求）。

## 提示

- "MCP 更高级" / "MCP 是未来" 都不是答案，写出来等于没写。
- 进程边界是核心：MCP 多一个 server 进程 = 多一份部署、监控、版本管理。
- tool schema 进 prompt 也吃 token，但不吃运维。

## 自检

- [ ] 写出 MCP vs tool calling 的本质区别（包含进程边界这一维度）
- [ ] 给出 1 个 MCP 合适的场景 + 1 个 MCP 不合适的场景
- [ ] 两个场景都能口头讲清楚为什么

## 提交（计入综合作业）

- 1 段 200 字以内的回答，归档到综合作业的"边界判断"目录

## 反例

- "MCP 是 tool calling 的升级版" → 不是升级关系，是不同层
- 把本地纯函数包成 MCP server → 给自己加运维负担（handbook D6b 反例 2）
- 只说"MCP 跨进程" 不说 "所以多一份运维成本" → 没讲到边界判断那一半
