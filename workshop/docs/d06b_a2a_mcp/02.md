# D6b-2: 在 A2A 链路上挂 MCP tool

> 时长：约 25 min ｜ 凭证：A2A 复用 D6b 主段产出或讲师 prepared repo；MCP 用本地实现 ｜ 类型：练

## 背景

这是 D6b 的核心实操：在已有的 A2A 链路（agent A → agent B）上，给 agent B 挂一个真实有副作用的 MCP tool（不准 echo）。目的是看到"叠加 = 双倍成本 + 双倍故障面"这件事在自己手上跑过一遍，决策卡的 token 增量栏才填得出。

跑不通不阻塞验收：A2A / MCP 至少一条本机跑通，另一条用 prepared repo / trace 对照即可，三段全本机不是硬要求。

## 你需要做什么

1. 准备 A2A 链路：
   - 优先：复用本模块**主段**（D6b 60 min 主段）跑通的 A2A demo（两个 agent，跨进程通信）。注意 D6a 只跑 SDK 重写的单 agent，**不产 A2A demo**。
   - Fallback：切到讲师 prepared repo，跑起 A2A 部分即可。
2. 准备一个最小本地 MCP server：
   - tool 必须有真实副作用（本地文件读取 / HTTP 请求 / 计算），不准 echo 输入。
   - 本地实现即可，**不依赖任何远端 MCP server**（包括 Foundry MCP server，rebrand 期不押）。
3. 把 MCP tool 接到 agent B 上，让 agent B 在响应 agent A 时会调用一次这个 tool。
4. 跑一次完整链路：发起请求 → agent A → agent B → MCP tool → 返回。

## 提示

- A2A 部分如果本机跑不起来，直接切 prepared repo，不要在 A2A 上死磕；本练习的产出是"叠加"。
- MCP tool 选"本地文件读取"最稳：副作用真实、不依赖外部服务、易于在 trace 里识别。
- 不要把"同进程函数调用"伪装成 MCP——下一步 trace 会被点名（handbook 反例 4）。

## 自检

- [ ] A2A / MCP 至少**一条本机跑通**；另一条用 prepared repo / trace 对照（与 handbook fallback 口径一致，不要求三 demo 全本机）
- [ ] MCP tool 有真实副作用（不是 echo）
- [ ] MCP server 是本地实现，不依赖远端
- [ ] 一次完整链路能从请求走到 MCP tool 再回来
- [ ] 叠加 demo 跑不通不阻塞 D6b 验收，但 token 增量栏要能填

## 提交（计入综合作业）

- A2A + MCP 代码目录（或 prepared repo 的引用 + 你这一侧加的 MCP tool 代码）
- 一次完整运行的日志或截图

## 反例

- MCP tool 只 echo 输入 → 没有副作用，等于没接（handbook 约束）
- A2A 两个 agent 同进程函数调用伪装 → 没学到 A2A 真实代价
- 接远端 MCP server（含 Foundry MCP）做主路径 → rebrand 期漂移高发，本课不押
