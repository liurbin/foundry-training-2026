# D6b-3: trace 对照 —— A → B → MCP tool

> 时长：约 10 min ｜ 凭证：本机 trace 或 prepared repo trace ｜ 类型：评审

## 背景

跑通不算数，trace 里数得出三段链路才算数。本步要求你打开 trace，明确看到 `agent A → agent B → MCP tool` 三个 span（或等价的链路节点）。同进程函数调用伪装成跨进程的，会被直接判负。

## 你需要做什么

1. 打开上一步运行后的 trace：
   - 本机跑通：Application Insights / 控制台 trace / SDK 的 trace 输出。
   - Fallback：打开讲师 prepared repo 的 trace 截图或导出文件。
2. 数出三段：
   - 第一段：发起方 → agent A
   - 第二段：agent A → agent B（必须是跨进程调用）
   - 第三段：agent B → MCP tool（必须是跨进程 MCP 调用）
3. 截图或导出 trace，标注三段链路。
4. 若 trace 里只有一个 span 或两个 span 套同进程函数 → 退回 D6b-2 检查是不是函数调用伪装。

## 提示

- "看不出来跨进程"通常意味着真的没跨——A2A 库用错 / MCP 接错。
- prepared repo 的 trace 也算数：本步关心的是"能不能数出三段"，不是"是不是你跑的"。
- 三段不全没关系（叠加 demo 跑不通不阻塞），但要老实写"我这里 trace 只到第 N 段"。

## 自检

- [ ] A2A / MCP 至少**一条本机跑通**对应的 trace 自己看了；另一条用 prepared repo / trace 对照（与 handbook fallback 一致，不要求三 demo 全本机）
- [ ] trace 里能数出三段：A → B → MCP tool（或老实标注断在第几段）
- [ ] 第二段（A → B）是跨进程，不是同进程函数
- [ ] 第三段（B → MCP）是跨进程 MCP 调用，不是 in-process 函数
- [ ] 截图 / 导出归档

## 提交（计入综合作业）

- trace 截图（或导出文件） + 三段标注
- 若断在中间：一句话说明断点位置 + 怀疑原因

## 反例

- "我代码里能看到 A 调 B" 但 trace 里只有一段 → 没真的跨进程
- 同进程函数调用伪装 → 直接判负（handbook 约束："同进程函数调用伪装直接判负"）
- 没 trace 工具就跳过 → 起码看 stdout / 进程列表证明跨进程
