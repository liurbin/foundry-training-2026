# D6b-4: A2A vs MCP 决策卡 + 成本估算

> 时长：约 15 min ｜ 凭证：无 ｜ 类型：评审

## 背景

前三步给你跑了 demo + 看了 trace，本步把它收成一张决策卡：4 个问题 + token 增量数字。叠加 = 双倍成本 + 双倍故障面，综合作业里有人选"我不引入"才正常——选不用也算过。

## 你需要做什么

1. 回答四问（每问写选择 + 一句理由）：
   - 我要让两个独立 agent 协作（各自有 LLM）？ → A2A
   - 我要让一个 agent 调结构化工具 / 资源？ → MCP
   - 既要又要？ → 叠加（必须算成本，见下）
   - 都不要（单 agent + 直接 function call 够）？ → 不引入，写明拒绝理由
2. 填成本影响栏：
   - A2A：多一次 agent 调用 = 多一倍 token + 一跳延迟
   - MCP：多一个 server 进程 / 网络跳；tool schema 进 prompt 也占 token
3. 写"我这个 demo 引入 A2A / MCP 后，每次请求 token 增加估算：__"——必须有具体数字（可粗估，但不能空）。
4. 给出最终选择 + 一句业务理由。

## 提示

- token 增量算不出来精确值就写区间（如 "+800~1500"）和一行计算依据。
- 决策卡选"不引入"完全合法 —— 综合作业不强制用 A2A / MCP。
- "为了学到所以引入"不是业务理由，砍掉。

## 自检

- [ ] A2A / MCP 至少**一条本机跑通**（上一步产物）；另一条用 prepared repo / trace 对照
- [ ] 决策卡四问全答，每问含选择 + 一句理由
- [ ] token 增量栏有具体数字（或合理区间 + 计算依据），不空
- [ ] 最终选择有业务理由（"不引入" 也算合法选择）
- [ ] 能口头讲清"我综合作业场景会不会用 A2A / MCP"

## 提交（计入综合作业）

- 决策卡文件（Markdown）
- 最终选择 + 业务理由段落

## 反例

- "A2A 更高级所以两个 agent 必须 A2A" → A2A 是协议不是必经路径
- 叠加 demo 跑通了就觉得"以后所有项目都 A2A + MCP" → 双倍成本 + 双倍故障面
- token 增量栏写"略" / 空 → 直接判负
- 选了叠加但没写成本估算 → 决策卡不算完
