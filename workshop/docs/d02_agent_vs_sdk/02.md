# D2-2: 4 维度打分与决策规则

> 时长：约 30 min ｜ 凭证：无 ｜ 类型：练（决策卡前半段）

## 背景
- 用第 1 步的职责理解，给你的项目在 4 个维度上各打 1-5 分
- 4 维度 = 托管运行时 / portal 可视化 / 代码控制 / 跨 provider 移植性
- 用启发式得出"Service / SDK / 混合"初步结论；成本估算放到第 3 步

## 你需要做什么
1. 拷入决策卡模板（同 handbook D2 spec），填上下文：

   ```markdown
   # Agent Service vs Agent Framework SDK 选型决策卡

   ## 上下文
   - 项目：[一句话]
   - 团队规模：[人数 + AI 熟手占比]
   - 是否需要非工程师在 portal 配 agent：[是/否]

   ## 四个维度打分（1-5，5 = 强需求）
   | 维度 | 分 | 说明 |
   |------|----|----|
   | 托管运行时（不想自己跑 worker） | _ | |
   | portal 可视化（PM/SA 直接配） | _ | |
   | 代码完全控制（自定义编排 / 自定义状态） | _ | |
   | 跨 provider 移植性 | _ | |
   ```

2. 4 个维度每个都打分（1-5，**不允许空**）
3. 套启发式得初步选择：
   - 前两项 ≥ 后两项 → Agent Service
   - 后两项 ≥ 前两项 → SDK
   - 接近 → 混合
4. 在"我的选择 + 理由"写 ≥3 句话，必须包含"是否符合启发式 + 不符合时为什么"

## 提示
- 打分不要全 3，要敢拉差距；全 3 等于没打
- 启发式输出 ≠ 最终结论；如果团队没人值班即便分数偏 SDK 也应该选 Service
- "混合"不是逃避，是真实路径（D6a/b 会回这条）

## 自检
- [ ] 4 维度全打分，无空白
- [ ] 初步选择与启发式一致；不一致时已写 1 句解释
- [ ] 理由 ≥3 句

## 提交（计入综合作业）
- 产物：决策卡前半段（上下文 + 4 维打分 + 初步选择 + 理由）
- 放：`submissions/d2_2_scoring/decision_card.md`（同一文件，第 3 步继续补成本部分）

## 反例
- 4 维度全打 3 —— 没有信息量，等于没决策
- "决策卡是 PM 填的，工程师不用关心" —— 这卡决定未来 6 个月 80% 实现路径
- "Agent Service 是托管的所以一定贵" —— 没算自托管的人力 + on-call
