# D3-2: 单 agent 跑通

> 时长：约 45 min ｜ 凭证：有 Foundry endpoint 学员自跑；无凭证用 mock 或讲师共享临时端点 ｜ 类型：实操

## 背景
- 第 1 步资源已部署，本步要从外部代码用 `agent_reference` 把 agent 调起来
- 借鉴上游 Ex02 单 agent 路径
- 必须捕获 429 / 5xx 并打日志，但具体重试策略推迟到 D5

## 你需要做什么
1. 把下面 prompt 给 AI，让它生成调用代码：

   ```text
   用 [Python / .NET / TS] 写一段最小代码调 Foundry agent：
   - 通过 agent_reference 拿到 agent
   - 发一句 "hello" 拿返回
   - 必须捕获 429 / 5xx 并 logging（重试逻辑这步不要写）
   - 不准 hardcode endpoint / key，走 env 或 Key Vault

   Project endpoint env var：FOUNDRY_PROJECT_ENDPOINT
   Agent id env var：FOUNDRY_AGENT_ID
   ```

2. 把 env 配好（有订阅用真值；无订阅短期可以指向讲师共享端点或下一模块的 mock）
3. 跑一次，确认返回 200 且文本非空
4. 主动注入一次错误（如把 agent_id 改错）确认 429/5xx 分支真的会被打到日志
5. 把成功调用的输出（含 1-2 行 log）保存

## 提示
- 不要在业务层写 retry，那是 D5 的事；本步只要"捕获 + 打日志"
- 如果你机器没有真 endpoint：先用占位 env 让代码能 import，D4 会引入 MockProvider 正式跑通
- agent_reference 的具体 API 形态可能在 rebrand 期漂移，以讲师 Day-7 验证后给的版本为准

## 自检
- [ ] 调用返回 200 且文本非空（无凭证学员：用 mock 或讲师端点跑通）
- [ ] 429 / 5xx 至少一条日志格式被验证过（主动错误注入）
- [ ] 代码里没有 hardcode 的 endpoint / key
- [ ] 能讲清"重试为什么不在这里写"

## 提交（计入综合作业）
- 产物：`call_agent.py`（或 .cs/.ts）+ 一次成功调用的日志片段
- 放：`submissions/d3_2_call_agent/`

## 反例
- agent_reference 调用代码没加任何 429/5xx 捕获 —— D5 压测 / D9 生产场景必炸
- 把 endpoint / key hardcode 进代码 —— 切环境就改源码
- 在业务层写 retry —— 多处重复 + 无 jitter，D5 会专门讲
